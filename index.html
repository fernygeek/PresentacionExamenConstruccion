Examen Práctico:
Mantenimiento de Software

Evolución, Instrumentación de Pruebas, Logs y Aseguramiento de la Mantenibilidad en Arquitectura CRUD

Proyecto: Examen/epn-event-manager (NestJS + TypeORM + SQLite)

Tema Funcional: CRUD de Platos Típicos Ecuatorianos

Entorno: Construcción de Software 2026

Contexto del Proyecto Base

  • Arquitectura Inicial: Aplicación backend modular construida sobre NestJS, utilizando TypeORM para la capa de persistencia con una base de datos local SQLite (db/platos-tipicos.sqlite).
  • Recurso Principal: Entidad PlatoTipico que contiene campos oficiales: id, nombre, descripcion, region, ingredientes, precio, imagenUrl y categoria.
  • Objetivo del Examen: Partir de un CRUD funcional inicial y aplicar de forma rigurosa las intervenciones técnicas normadas para mitigar la deuda técnica intencional expuesta.

Diagnóstico de Deuda Técnica Inicial

Identificación crítica de carencias estructurales antes del proceso de estabilización:

  • Pruebas y Cobertura: Cobertura automatizada nula o extremadamente limitada para los flujos críticos de persistencia y operaciones CRUD.
  • Seguridad y Validación: Ausencia de API Keys para asegurar endpoints, validaciones de entrada incompletas y vulnerabilidad a entradas maliciosas.
  • Observabilidad y Documentación: Falta de trazabilidad interna mediante logs estructurados, ausencia de metadatos adaptativos en las respuestas y carencia de especificación OpenAPI/Swagger.

Metodología TDD (Test-Driven Development)

  • Flujo Riguroso de Trabajo: Cada una de las fases de mantenimiento del examen se rigió bajo el ciclo clásico de desarrollo guiado por pruebas:
    • Fase RED: Creación e instrumentación de pruebas automatizadas e2e diseñadas específicamente para fallar.
    • Fase GREEN: Implementación del código productivo mínimo necesario para satisfacer las condiciones de la prueba.
    • Fase REFACTOR: Optimización de la arquitectura y legibilidad del código sin alterar su comportamiento externo verificado.
  • Métricas de Cierre: 24 pruebas de extremo a extremo (e2e) ejecutadas con éxito (GREEN) que garantizan cero regresiones en la capa persistente.

Mantenimiento Correctivo

  • Problema Inicial Detectado: Existía riesgo latente de éxito falso en la eliminación de registros (DELETE /platos-tipicos/:id) o un manejo no controlado ante identificadores inexistentes.
  • Cambio Realizado: Se blindaron e implementaron pruebas e2e robustas en test/platos-tipicos.e2e-spec.ts para certificar la eliminación real en SQLite y el retorno correcto de un código de error HTTP 404 ante IDs inexistentes.
  • Impacto Estratégico: Eliminación de respuestas ambiguas, asegurando un control granular de excepciones y total confiabilidad en la persistencia local de datos.

Mantenimiento Adaptativo

  • Problema Inicial Detectado: Las respuestas del API carecían de contexto global y metadatos unificados necesarios para la integración armónica con el ecosistema de EPN Event Manager.
  • Cambio Realizado: Inclusión de una capa envolvente que inyecta metadatos adaptativos a las respuestas (timestampISO, timezone, apiVersion, environment e integrationTarget).
  • Impacto Estratégico: El contrato de la API queda completamente preparado para integraciones futuras sin alterar ni acoplar el modelo físico o de negocio de PlatoTipico.

Mantenimiento Perfectivo

  • Problema Inicial Detectado: El sistema inicial poseía un valor funcional básico, desprovisto de herramientas visuales orientadas al usuario final y de métricas de agregación interna.
  • Cambio Realizado:
    • Desarrollo e integración de un nuevo endpoint optimizado de estadísticas analíticas (GET /platos-tipicos/stats).
    • Construcción de una interfaz frontend ágil, moderna y funcional utilizando Node.js + Vite para la visualización e interacción con el CRUD.
  • Impacto Estratégico: Incremento sustancial del valor comercial y operativo del sistema, optimizando la experiencia del usuario y la toma de decisiones.

Mantenimiento Preventivo y Seguridad

  • Problema Inicial Detectado: Alta vulnerabilidad ante inyecciones, manipulación errónea de datos por desbordamiento de cadenas, campos vacíos o valores numéricos negativos.
  • Acciones Implementadas:
    • Sanitización Rigurosa: Reglas estrictas de validación de tipos, limpieza con trim, bloqueo activo de etiquetas <script> y patrones de inyección SQL.
    • Seguridad por API Key: Resguardo perimetral de endpoints protegidos mediante la inclusión obligatoria de la cabecera X-FIS-EPN-KEY validada por un ApiKeyGuard.
  • Impacto Estratégico: Blindaje completo del entorno de ejecución, previniendo fallos operacionales en producción antes de que ocurran.

Observabilidad y Trazabilidad de Auditoría

  • Logs Estructurados: Instrumentación del Logger nativo de NestJS para registrar eventos operacionales clave (trazas INFO) y violaciones de seguridad o validaciones fallidas (trazas WARN).
  • Documentación API: Exposición interactiva del contrato de servicios mediante Swagger/OpenAPI disponible en la ruta local /api/docs.
  • Integración Continua (CI): Automatización de tuberías de validación mediante GitHub Actions (.github/workflows/node-ci.yml), garantizando la ejecución transparente de pruebas unitarias, e2e, linting y builds limpios tanto en backend como en frontend.

Conclusiones del Proceso

  • Estabilización Arquitectónica: Se demostró de manera medible y reproducible que un sistema con deuda técnica puede ser transformado en una solución robusta, observable y segura mediante la aplicación rigurosa de estándares de ingeniería de software.
  • Garantía de Calidad: La suite de pruebas TDD e2e actúa como una red de seguridad infalible contra regresiones funcionales en operaciones de persistencia.
  • Preparado para Producción: La combinación de logs estruturados, protección perimetral por API Key, documentación interactiva y flujos automatizados de CI elevan la solución a niveles aptos para el despliegue corporativo institucional.
